# 每日高 / 低點判斷網頁:可行性評估(2026-11-02)

這一階段只評估可行性和設計畫面,沒有寫正式程式,也沒有訓練模型或跑回測。
下面的數字都來自既有結果檔(`results/confusion_2024_2026_tw100.json`、`results/backtest_long_only*.json`)。

## 結論

**有條件可行。** 技術上不難:資料量小,推論不到 1 秒,每天跑一次批次就夠。
真正的限制在「判斷準不準」和「能不能公開」:

| 限制 | 說明 | 處理方式 |
|---|---|---|
| 命中率約 3 成 | 判低點只有 27–33% 真的是 11 天最低(2024–2026,TW100 主軸) | 每個判斷旁邊都顯示信心分數和歷史命中率,不寫「買進」 |
| 照著做多半虧錢 | 只做多前 3 檔,扣成本後 TW100 三年是 +11.7% / −42.2% / +8.7%,TW200 三年都虧 | 回測成績放在每個建議旁邊,和建議一起出現 |
| 答案要 5 天後才知道 | 標籤看 t+5,今天的判斷 5 個交易日後才能對答案 | 成績追蹤頁顯示「待驗證」狀態 |
| 法規 | 公開對不特定人提供個股買賣建議,可能碰到投顧法規 | 第一版只給自己或研究團隊用,不公開、不收費、不放廣告 |
| 池外股票沒驗證過 | 模型只在 73 檔上訓練和測試 | 可以算,但要加明顯的警示 |

## 1. 資料

### 1-1 每日 K 線什麼時候拿得到

| 來源 | 收盤後多久有資料 | 備註 |
|---|---|---|
| 台股收盤 | 13:30(盤後定價交易到 14:30) | 收盤價 13:30 就確定,成交量要等盤後交易結束才是全天數字 |
| 證交所 / 櫃買中心盤後資料 | 約 14:30–15:30 | 官方資料,最準 |
| yfinance(Yahoo) | 通常 14:00–16:00,偶爾延到晚上或隔天 | 最後一根偶爾缺量或數字不對,隔天才修正 |

**建議**:每天 **18:00** 跑批次。先檢查每檔最後一天是不是今天;有缺的檔在 20:00、22:00 再補抓兩次,還是缺就標「資料未更新」,不出判斷。
假日、颱風停市沒有新 K 線,批次就直接沿用前一天的畫面,頁面上寫「今日休市」。

### 1-2 yfinance 穩定度與替代來源

| 來源 | 優點 | 缺點 | 建議用途 |
|---|---|---|---|
| yfinance(目前用的) | 免費、已有快取、有還原價 | 非官方 API,常改版或擋流量;最後一天資料偶爾有錯 | 第一版主要來源 |
| 證交所 OpenAPI / 盤後資訊(上市) | 官方、免費;一次呼叫拿到全部上市股票當天的資料 | 沒有還原價,要自己用除權息資料算 | 每天核對 yfinance 的收盤價;以後擴大到全市場時當主要來源 |
| 櫃買中心盤後資料(上櫃) | 官方、免費 | 同上 | 開放上櫃股票查詢時才需要 |
| FinMind | 有整理好的 API,含還原價 | 免費版有呼叫次數限制 | 備援 |
| TEJ 等付費資料 | 品質最好 | 要付費 | 正式對外服務時才考慮 |

**建議**:第一版用 yfinance,另外抓證交所當天收盤價做核對,兩邊差超過 0.5% 就把該檔標成「資料待確認」。

### 1-3 還原價的影響

目前 `fetch_yfinance` 用 `auto_adjust=True`,也就是還原價(把除權息的跳空補回去)。

| 項目 | 影響 | 處理方式 |
|---|---|---|
| 特徵 | 特徵是開高低收 ÷ t 日收盤、量 ÷ 10 日均量。如果用原始價,除息日那天會出現一個假的跳空下跌,容易被判成低點候選 | 繼續用還原價,和訓練時一致 |
| 歷史會變 | 每次除權息,之前的還原價都會整段重算,過去的判斷重算一次可能不一樣 | 每天的判斷當天就存檔(凍結),之後不重算;對答案也用存檔時的判斷 |
| 畫面上的價格 | 還原價和看盤軟體上的價格不同,使用者會困惑 | 畫面上顯示原始收盤價,K 線圖註明「還原價」 |

## 2. 模型

### 2-1 用哪個股票池訓練

| 股票池 | 檔數 | 2025 macro-F1(主軸) | 只做多前 3 檔,扣成本 2024 / 2025 / 2026 |
|---|---|---|---|
| 34 檔(台灣50 剔除 16 檔) | 34 | 53.14% | −24.8% / −34.9% / +0.1% |
| **TW100 剔除後** | **73** | **53.75%** | **+11.7% / −42.2% / +8.7%** |
| TW200 剔除後 | 168 | 沒算分類 | −16.5% / −44.0% / −17.6% |

**建議用 TW100 73 檔**:分類成績最好,而且是目前 `mainline.load_data()` 的預設,不用改程式。
TW200 回測三年都虧,先不用。

### 2-2 顯示哪個方法

TW100 73 檔,2024–2026 每年的成績(%):

| 方法 | macro-F1 | 判低點命中率 | 判高點命中率 | 真低點找到率 | 每天平均判低點檔數 |
|---|---|---|---|---|---|
| ① 主軸 | 53.3 / 53.8 / 53.4 | 27.4 / 29.0 / 32.9 | 28.0 / 27.6 / 24.4 | 86.9 / 81.6 / 65.1 | 約 15 檔 |
| ② Stacking | 50.2 / 49.9 / 50.2 | 25.9 / 27.2 / 29.8 | 26.4 / 26.5 / 22.4 | 54.3 / 42.9 / 50.2 | 約 8 檔 |

- 兩個方法的命中率差不多,主軸找到的高低點多一倍。
- 只做多前 3 檔的回測,兩個方法每年互有勝負(2024 主軸好,2025、2026 Stacking 好)。
- 參考:隨便挑一天,剛好是 11 天最低點的機率約 7%。判低點命中 29% 大約是隨便猜的 4 倍,但還是 10 次錯 7 次。

**建議**:預設顯示 ① 主軸,可以切換到 ② Stacking;個股頁兩個並排比較。兩個方法都判低點時加「兩方法一致」標記。
(兩方法一致時的命中率目前沒算過,動工後第一件事是算這個,如果明顯比較高,可以當推薦清單的排序依據。)

### 2-3 多久重訓、推論速度

| 項目 | 建議 | 理由 |
|---|---|---|
| 重訓頻率 | **每年 1 月重訓一次**(前 4 年資料,例如 2027 年用 2023–2026) | 和研究的 walk-forward 設定一致,歷史命中率才能直接引用 |
| 模型存檔 | 每年的模型存成檔案,記下訓練期間和種子 42 | 畫面上要能顯示「目前模型:訓練 2022–2025」 |
| 推論速度 | 73 檔 × 29 維,一次推論不到 1 秒 | 瓶頸是抓資料(yfinance 約 1–3 分鐘) |
| 重訓時間 | 幾分鐘(CPU) | 一年一次,不用 GPU |

## 3. 「每日推薦」怎麼產生

| 步驟 | 內容 |
|---|---|
| 1 | 收盤後抓 73 檔的 K 線,每檔取最後 6 根算 29 維特徵 |
| 2 | 兩個方法各跑一次,得到每檔的 高點 / 低點 / 非極值 和分數 |
| 3 | **判低點清單**:判低點的股票依分數排序,前 3 檔放在最上面(和回測的「前 3 檔」一致),其餘收在「還有 N 檔也判低點」 |
| 4 | **判高點清單**:同樣做法,前 3 檔 + 展開 |
| 5 | 每檔附上:今天收盤價、分數、信心等級、同等級的歷史命中率、兩方法是否一致 |
| 6 | 整份結果存成當天的 JSON(凍結),5 個交易日後自動對答案 |

- **推幾檔**:建議 **前 3 檔**,因為回測就是用 3 檔,成績可以直接對應。主軸每天平均判低點約 15 檔,全部列出會讓人以為都值得買。
- **判高點怎麼用**:研究只回測過「判低點做多」。判高點沒有獨立的回測(只有瑞昱單檔的反手實驗),所以判高點清單定位成「提醒:可能是近期高點,不宜追高」,不寫成賣出建議。

## 4. 使用者輸入股票

### 4-1 不在股票池裡的股票能不能判斷

技術上可以:特徵只用自己的 6 根 K 線和 10 日均量,任何有 15 天以上資料的股票都算得出來。但準不準沒有驗證過。

| 股票類型 | 例子 | 能不能算 | 建議顯示方式 |
|---|---|---|---|
| 池內 73 檔 | 台積電、瑞昱 | 可以,有歷史命中率 | 正常顯示 |
| TW100 / TW200 裡被剔除的低波動股 | 中華電、兆豐金 | 可以算,但沒意義:每天漲跌太小,「11 天最低」常常只差幾毛錢 | **顯示「不適用」**,分數收起來,要點開才看得到 |
| 池外一般上市股票 | TW200 多出來的 95 檔 | 可以算 | **黃色警示**「這檔不在訓練股票池,判斷沒有驗證過」 |
| 上櫃、興櫃、ETF、權證 | 6488、0050 | 第一版不支援 | 自動完成清單裡不出現;輸入代號時說明「目前只支援上市普通股」 |
| 新上市不到 15 天、停牌、處置股 | — | 資料不足或不正常 | 顯示「資料不足」或「交易受限」 |

**可以補的驗證**:TW200 168 檔扣掉 TW100 的 73 檔,剩下 95 檔可以當「池外」測試,算出池外命中率。動工後順便算,畫面上池外股票就能顯示「池外股票歷史命中率 xx%」,而不是只寫「沒驗證過」。

### 4-2 風險與畫面提示

| 風險 | 畫面提示 |
|---|---|
| 使用者把「判低點」當成「會漲」 | 結果卡片固定寫:「低點 = 今天收盤可能是前後 11 天最低,不代表之後會漲多少」 |
| 只看到判斷,沒看到命中率 | 判斷、信心、歷史命中率放在同一行,不能分開 |
| 池外 / 低波動股 | 黃色或灰色標籤,警示放在判斷結果的上面 |
| 資料沒更新 | 頁首顯示資料日期;不是今天就整頁加紅色橫條 |
| 盤中查詢 | 盤中查到的是昨天收盤的判斷,畫面寫「判斷基準日:11/02 收盤」 |

## 5. 「建議」怎麼寫才誠實

### 5-1 建議文字的原則

| 原則 | 做法 |
|---|---|
| 不用命令句 | 不寫「建議買進」,寫「模型判斷:今天可能是低點」 |
| 信心和命中率一起出現 | 「信心:高(分數 0.82)。過去同等級的判低點,31% 真的是低點」 |
| 對應回測規則 | 「研究的回測規則:明天開盤買、第 5 個交易日收盤賣。這個規則在 2024 / 2025 / 2026 扣成本是 +11.7% / −42.2% / +8.7%」 |
| 講清楚錯的時候怎樣 | 「錯的時候大多是判成非極值的普通日子,不會把高點判成低點(過去三年 0 次)」 |
| 每次都有免責 | 卡片底部一行小字 + 連結到說明頁 |

### 5-2 信心等級怎麼分

把分數依歷史分布切成 高 / 中 / 低 三等(各約 1/3),每一等都附上 2024–2026 的實際命中率。
這樣「信心高」對應的是一個實際的數字,而不是模型自己說的機率。
(目前沒算過各等級的命中率,要等動工後用已有的 walk-forward 預測算出來。如果三個等級的命中率差不多,就不分等級,只顯示分數。)

### 5-3 成績追蹤(過去推薦事後對答案)

| 項目 | 內容 |
|---|---|
| 存什麼 | 每天的推薦清單(凍結,不重算)、當時的收盤價、分數 |
| 何時對答案 | t+5 收盤後,用同樣的標籤規則判斷是不是真高 / 低點 |
| 對答案的結果 | 對 / 錯 / 待驗證(還沒滿 5 天);另外記「t+1 開盤買、t+5 收盤賣」的報酬(扣成本 0.585%) |
| 顯示什麼 | 近 20 天、近 60 天、今年的命中率;每日明細表;模擬報酬曲線 |
| 上線前的資料 | 用 2024 年起的 walk-forward 結果回填,標成「回測期」,和上線後的「實際追蹤」用不同顏色分開 |

## 6. 法規風險

> 以下是一般性整理,不是法律意見。要公開或收費之前,請找律師或向投信投顧公會確認。

| 法規 | 重點 | 對這個系統的意思 |
|---|---|---|
| 證券投資信託及證券投資顧問法 第 4 條 | 「證券投資顧問」是指直接或間接從委任人或第三人取得報酬,對有價證券提供分析意見或推介建議 | 收會員費、放廣告、導流賺佣金,都可能算「間接取得報酬」 |
| 同法 第 107 條 | 沒有許可經營投顧業務,可處 5 年以下有期徒刑,併科罰金 | 收費或商業化前一定要確認 |
| 投顧事業管理規則 | 即使是有照投顧,透過網路、媒體推介個股也有很多限制(例如不得保證獲利、要揭露風險) | 公開對不特定人推個股,風險最高 |
| 證券交易法 第 155 條 | 散布不實資訊影響股價 | 推薦清單不要誇大、不要配合買賣 |

**依用途分的建議:**

| 用途 | 風險 | 做法 |
|---|---|---|
| 只有自己用(本機) | 低 | 免責一行即可 |
| 研究團隊 / 課堂展示(要登入、少數人) | 低–中 | 加登入、不收費、不放廣告;每頁免責;用「研究結果展示」的定位 |
| 公開網站、免費 | 中–高 | 不建議;至少拿掉「推薦」字眼,改成「模型判斷紀錄」,並請律師看過 |
| 收費或有廣告 | 高 | 需要投顧執照,不建議 |

**免責文字(建議版)**:

> 本網站為個人學術研究之模型輸出展示,非證券投資顧問服務,不構成任何買賣建議或推介。
> 模型歷史命中率約 3 成,依研究回測規則操作在多數年度扣除成本後為虧損。
> 投資有風險,請自行判斷並承擔損益。本網站不收取任何費用,亦無廣告或任何形式之報酬。

畫面上的用詞:頁面名稱用「今日判斷」而不是「今日推薦」,按鈕不用「買進 / 賣出」。

## 7. 技術架構建議

### 7-1 兩種做法比較

| 項目 | A. 每日批次產生 JSON + 靜態前端(建議) | B. FastAPI 後端 + 前端 |
|---|---|---|
| 運作方式 | 每天 18:00 跑 Python 腳本,產生 `today.json`、每檔一個 `stock/2330.json`、`track.json`;前端只讀檔案 | 使用者查詢時後端即時抓資料、跑模型 |
| 池外股票 | 批次時把要支援的股票都先算好(上市約 1,000 檔,推論還是不到幾秒,但抓資料要用證交所批次資料) | 隨時可以算任何股票 |
| 判斷可重現 | 每天的 JSON 就是存檔,天然凍結 | 要另外存 |
| 主機需求 | 不需要伺服器 | 要一台一直開著的主機 |
| 維護 | 少 | 多(要處理流量、錯誤、yfinance 被擋) |
| 費用 | 可以 0 元 | 雲端主機每月約 5–20 美元 |

**建議 A**。股票池固定,每天只更新一次,不需要即時計算。

### 7-2 部署選項

| 選項 | 適合 | 備註 |
|---|---|---|
| **本機**:排程(cron / 工作排程器)+ 本機開網頁 | 只有自己用 | 最簡單,電腦 18:00 要開著 |
| GitHub Actions 排程 + 私人網頁 | 想用手機看 | GitHub Pages 用私人 repo 要付費方案;公開 repo 等於公開網站(看第 6 節) |
| Cloudflare Pages + Access 登入 | 研究團隊少數人 | 免費方案可以設登入名單 |
| 雲端主機跑 FastAPI | 以後要即時查任何股票 | 第一版不需要 |

**建議**:第一版**本機**;要用手機看再換 Cloudflare Pages 加登入。

### 7-3 工作量估計

| 工作 | 內容 | 天數 |
|---|---|---|
| 批次腳本 | 抓資料、核對、兩方法推論、凍結存 JSON | 2 |
| 對答案與成績 | t+5 對答案、命中率、模擬報酬;用 2024 起的結果回填 | 1.5 |
| 補算統計 | 信心等級命中率、兩方法一致命中率、池外 95 檔命中率 | 1 |
| 前端 4 頁 | 照示意稿做,含 K 線圖、自動完成、手機版 | 3 |
| 排程與部署 | 本機排程;可選 Cloudflare Pages | 0.5–1 |
| 測試 | 休市日、資料缺漏、除權息日 | 1 |
| **合計** | | **約 9–10 個工作天** |

## 8. 結論

**有條件可行。** 條件:

1. 定位成「研究模型的每日判斷紀錄」,不公開、不收費、不放廣告。
2. 每個判斷都和歷史命中率、回測成績一起顯示,不寫「買進 / 賣出」。
3. 有成績追蹤頁,每天的判斷存檔不改,5 天後自動對答案。
4. 池外股票可以查,但要有警示;低波動股顯示「不適用」。

主要限制:命中率約 3 成、照回測規則做多數年度扣成本是虧的、答案要 5 天後才知道、yfinance 不是官方資料、公開提供有投顧法規風險。
