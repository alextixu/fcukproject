## 一、全流程輸入輸出總覽(審查結論)

### 1. data_loader(`core/data_loader.py`)
- **輸入** ticker 清單(TW50/TW100/TW200/SSE50)+ start/end 日期字串。
- **處理** 逐檔 `yf.download(auto_adjust=True)` → 攤平欄位、轉小寫、留 OHLCV 五欄 → `dropna()` → 寫 `./cache/{tk}_{start}_{end}.parquet`;命中快取則原樣讀回。
- **輸出** `dict{ticker: DataFrame(~1700列×5欄)}`,tz-naive DatetimeIndex,給 dataset / indicators 使用。
- **確認正確**:快取讀寫格式一致(實測 279 檔)、快取內 NaN=0、無時區錯位、單 ticker MultiIndex 攤平正確、現存快取皆產於 auto_adjust=True 之後(無舊資料污染)、春節 13 天 gap 為正常休市、除權息還原比值不變故標籤不受影響。

### 2. indicators(`core/indicators.py`)
- **輸入** OHLCV DataFrame + 窗口 n + 可注入 `stats=(mean,std)`。
- **處理** 9 指標(SMA/WMA/MOM/MACD/W%R/CCI/K%/D%/RSI)全為 rolling/shift/ewm 因果運算 → `nan_to_num` 填 0 → z-score(stats=None 用本 df 全期;`(0,1)` = 原始值)。
- **輸出** `(T,9) float32`,與輸入 df 逐列對齊。
- **確認正確**:9 個公式皆只用 ≤t 資料,無 lookahead;WMA 權重無 off-by-one;輸出逐列對齊,標籤 close[end] vs close[end-1] 無洩漏;正常路徑測試集皆注入訓練統計量或 raw (0,1);XGB 變體 B 的 stats=(0,1) 等同原始指標且無統計量洩漏;warmup=2×window 足以覆蓋 rolling 暖機。

### 3. PIP + Visibility Graph(`core/pip_algorithm.py`, `core/vg_graph.py`)
- **輸入** window 內 raw close 序列 + m(關鍵點數)。
- **處理** 首尾固定,迭代選「到左右鄰 PIP Euclidean 距離和」最大的點(增量重算);對 PIP 兩兩檢查中間點遮擋建 natural visibility graph。
- **輸出** m 個窗內相對索引 + importance scores;nx.Graph(節點屬性 time/price)。
- **確認正確**:切片無 off-by-one;增量重算與樸素版等價(20 次隨機測試);VG 定義符合標準(等號遮擋、非等距內插正確);節點 time 索引與 close/feats 切片同座標系,無日期錯位;窗內無未來資料。
- ⚠ 但距離公式本身有尺度問題,見二-P3。

### 4. subgraph(`core/subgraph.py`)
- **輸入** VG 圖 + scores + `(window,F)` 指標矩陣 + N, g。
- **處理** 依 (importance, degree, 鄰居 importance) 選 N 個核心節點 → BFS 整層擴至 ≥g → 依 (depth, importance, degree) 截斷至 g、不足補 dummy → 以節點 time 取當日指標列。
- **輸出** `X (N,g,F) float32`。鄰接矩陣刻意丟棄(模型實為 CNN+attention,圖結構經 BFS 排序隱式編碼,docstring 有載,非缺陷)。
- **確認正確**:0 個發現。索引對齊、無未來資料、補零防護恆真、BFS/截斷與論文 3.2.1-3.2.2 一致、padding 正確。

### 5. dataset(`core/dataset.py`)
- **輸入** stock_data dict + window/m/N/g/stride/norm_stats/min_date。
- **處理** 滑窗產描述子(特徵窗 rows [end-window, end-1]、決策日 = row end-1、**label = close[end] > close[end-1]**,平盤=0)→ 依 (決策日, ticker) 排序 → 預配置 X_all,ProcessPool 保序填入,失敗樣本截尾。
- **輸出** `X (n,N,g,9)`、`y (n,)`、`meta [(ticker, 決策日)]`、date_to_indices;npz 快取 roundtrip 保序。
- **確認正確**:標籤無直接洩漏(close[end] 只進標籤);train/test 決策日集合不相交(min_date 過濾 warmup);X/y/meta 對齊(含失敗截尾與 npz 存讀);形狀一致;split_by_date 無索引錯位。

### 6. model(`core/model.py`)
- **輸入** `(B,N,g,F)`。paper_exact=True:Conv(g,F)→Conv(5,1)→Conv(N-4,1)→FC→**batch 維 self-attention(Eq.7-9, 無縮放無殘差)**→classifier;False:加 BN/dropout/殘差/縮放的舊改進版。
- **輸出** logits `(B,2)`。
- **確認正確**:兩路徑 flat_dim 一致;reshape/permute 不錯位;不用鄰接矩陣是有文件的設計;n_classes 與標籤相容。
- ⚠ attention 對 batch 維運作是重大問題來源,見二-P1/P2。

### 7. train(`core/train.py`)
- **輸入** train/val(torch random_split 80/20)+ test(依日期另建)。
- **處理** Adam + CE;每 epoch 以 val macro-F1 保留最佳權重;test 只在最後評一次。'date' 模式有正確的 Subset 索引重映射。
- **確認正確**:loss 加權平均正確;指標計算正確;train/test 日期邊界乾淨;grid search 只用 val 選參;'paper' 模式可依 seed 重現。

### 8. runners(`test/run_paper_repro.py`, `run_xgb_baseline.py`, `grid_search_paper.py`)
- **確認正確**:三腳本 dscache key 逐字元同構(tw/cn 快取實際存在且吻合);npz roundtrip 保序;XGB 變體 B 的 (ticker,決策日)→9 指標查表對齊正確、無前視;XGB early stopping 只用 train 內部切分,測試集無污染;md 表格與論文對照數字核對無誤。

## 二、確認的問題(經對抗驗證通過)

### P1【high】測試/回測時 self-attention 跨樣本洩漏未來資訊
`core/model.py:159-160` 的 attention 是對 **batch 維度**做的(`softmax(Q@K^T)` 為 B×B)。dataset 依 (決策日, ticker) 排序、`train.py:126` 測試 DataLoader 以 shuffle=False 連續切 128 筆 → 同一批混入同股票決策日 t 與 t+1 的樣本;t+1 樣本的輸入窗含 close[t+1],正是 t 樣本標籤的決定值 → t 樣本的預測可經 attention 讀到自己的答案。
**驗證者實測(3/3 票通過,含用實際 checkpoint 重現)**:
- rawfeat 模型:sorted bs=128 **Acc 52.70%** vs bs=1(無跨樣本混合)**46.82%**(差 +5.9pp、63.79% 預測翻轉);同日批('date')**51.30%** → 其中約 +1.4pp 是「未來日樣本」專屬貢獻。
- raw 模型 attention 近乎 one-hot(winner mass ≈ 0.9997),30~34% 測試樣本的 attention winner 是決策日更晚的樣本。
- 擾動同批未來樣本的輸入會改變早期樣本 logits(梯度路徑非零),機制確鑿。
**影響**:experiments_paper/ 與 chinatest/ 幾乎全部記錄與回測都走 batch_mode='paper',**歷史 test 數字普遍含此批次效應**(方向不保證一律偏樂觀,但 raw 模型 acc 確被墊高)。'date' 模式無此洩漏。
**注**:此為論文 Eq.7-9 的忠實復現(docstring 有明載),屬「論文方法本身的缺陷」而非打字錯誤——這本身是可報告的復現發現。

### P2【medium】同一樣本的預測隨 batch 組成/大小改變
同一機制的另一面:B=1 時 attention 退化為恆等;尾批(<128)支撐集不同;移除 1 筆樣本使批界移動後其餘 164/164 筆 logits 全變。**票數 1 上持 / 1 反駁**(反駁者指出:固定協定下 evaluate 與 backtest 批界完全相同、逐位元可重現,且無單樣本部署路徑,故實務閉環內一致)。結論:**指標在固定協定內可重現,但數字綁定批次協定**,不能與逐日部署或不同 batch 設定比較。

### P3【medium】PIP 距離公式把「天數」與「原始價格(元)」混進同一 Euclidean 距離
`core/pip_algorithm.py:44-45`,且 dataset 傳入未正規化 raw close。**3/3 票通過,實測重現**:同形狀序列 25 元 vs 250/750 元,選出的 PIP indices 大幅不同(平均重疊僅 ~30/40、最終 X 張量 98.7% 元素不同)→ 台股 20~1000 元價位混池下,跨股票「chart importance」語意不一致。`融合實驗報告.md` B-1 已提出修法(窗內轉報酬率、時間軸正規化),core 尚未修。

### P4【medium】train/val 用 random_split 切重疊滑窗樣本,val 選 epoch/選參被污染
stride=1 時相鄰樣本共享 139/140 列;實測 79.7% val 樣本的同股次日樣本落在 train(輸入窗含 val 標籤日收盤),且 100% val 決策日同時出現在 train(同日跨股票市場 beta 通道)。**票數 2 上持 / 1 反駁**(反駁者實證:歷史 24 筆實驗 val_f1m 並未系統性高於 test,多數 run 塌縮至先驗,實際污染幅度有限)。結論:**機制屬實但在 ~50% 天花板下實害有限**;學到東西的 run(如 gridbest val 0.499 vs test 0.351)確實可能選到不泛化組態。`experiments_fusion` 已有 C-2 時間序 val 修法,未回移 `test/main.py` 與 `run_paper_repro.py`。

## 三、待複驗的發現(對抗驗證因額度中斷未跑完;證據具體度高者先列)

### 已另行人工/實測確認(4 項)
1. **【medium】yfinance `end` 為右開區間**:`end="2024-12-31"` 實際只抓到 2024-12-30(審查員實測 230 個快取檔的最後一列全為 12-30,而 12-31 是台股交易日)→ 測試集/回測缺最後一個交易日。`core/data_loader.py:334`。
2. **【medium】volume=0 假 bar 未過濾**:實測 279 檔共 3,482 列 volume=0、其中 3,447 列 OHLC 全等於前日收盤(yfinance 補列)→ 標籤在假 bar 上必為 0(跌),3,400+ 樣本系統性偏跌。`core/data_loader.py:341`。
3. **【low】滑窗上界 off-by-one**:`range(window, len(df) - 1, stride)` 使每檔最後一個合法樣本(決策日=倒數第二個交易日)永不建構(已直接讀碼確認,`core/dataset.py:86`)→ 每檔 train/test 各少 1 筆。正確為 `range(window, len(df), stride)`。
4. **【medium】XGB 與 Chart-GCN 的 80/20 切分實際不同**:XGB 用 numpy PCG64、GCN 用 torch randperm,同 seed=42 排列不同 → 先前 md 寫「同 seed 隨機 80/20 切分」不精確(兩者皆為 train 內部隨機 80/20、無測試集污染,對照仍公平,但記錄措辭需更正)。`test/run_xgb_baseline.py:82-85`。

### 尚未複驗(證據具體但缺獨立驗證)
- 【medium】單 ticker 下載失敗(空 df / rate-limit)被靜默 continue,只有全部失敗才 raise → 股票組成在不同執行間可能不穩定(`data_loader.py:335-336`)。
- 【medium】z-score 模式下,訓練段不足 window+1 列的股票缺 norm_stats,測試集靜默 fallback 用「測試期自身全期」統計量 → 該股測試特徵前視(`dataset.py:78` → `indicators.py:90-92`;**raw 模式不受影響**,故 rawfeat/XGB 主要數字無此問題)。
- 【medium】Momentum 前 n-1 列 NaN 被填 0,訓練集無 warmup 過濾 → 每檔前 ~window-1 個訓練樣本含人工 0 值,且 stats=None 時統計量被污染(`indicators.py:87`)。
- 【medium】`paper_exact` 預設 True 使 experiments_fusion 舊呼叫端靜默改跑論文架構、dropout 引數變 no-op → 融合實驗重跑時新舊數字不可比(`model.py:43`;融合實驗需顯式傳 `paper_exact=False`)。
- 【low】訓練集 z-score 用全訓練期統計量(in-sample 前視,test 評估不受影響)(`indicators.py:91`)。
- 【low】測試段 EMA/MACD 自 warmup 截斷點重起算,與訓練(全歷史遞迴)語意不一致,測試初期有小偏移(`dataset.py:195`)。
- 【low】價格快取 key 不含 auto_adjust/下載日,且 `./cache` 相對 cwd(專案已有 cache/ 與 core/cache/ 兩份);dscache key 不含資料版本與 ticker 清單內容 → 資料更新後靜默命中舊快取、XGB 變體 B「新價格特徵 × 舊快取標籤」可能漂移(`data_loader.py:329`、`run_paper_repro.py:146`)。

### 6.1 標準協定(從今起的預設)

**date 批次(同日全股票一批)= 無洩漏,且與論文文字相容**。論文 4.2/4.3 只說
「add a self-attention layer between S samples」「to explore the inner connection between stocks」,
**從未定義 S 是哪些樣本**。「同一天的 S 檔股票」這個解讀既符合「股票間內在關聯」的動機、又天然無洩漏;
「連續 128 筆」解讀(舊 'paper' 模式)才會把明天的樣本混進來。日後所有論文對齊實驗一律 `--batch-mode date`。

### 7.1 回測邏輯(backtest.py)— 影響「超額報酬」數字的可信度

1. 【med】**benchmark 股票池 ≠ 策略股票池**:benchmark 對全部 stock_data 算買入持有,策略只含有預測的股票(歷史不足/PIP 失敗的股票被排除)→ 超額報酬不公平(`backtest.py:138` vs `170-172`)。

5. 【low】策略端 ffill 凍結尾端持倉淨值、benchmark 續算實價 → 尾端口徑不對稱(`backtest.py:179-182`)。
6. 【high/慣例】**執行時序假設**:訊號需當日完整 OHLC(收盤後才可得)卻以同日收盤價成交(台股收盤撮合 13:25 截單)→ 回測報酬系統性偏樂觀;加上零交易成本(台股一回合 ~0.585%,策略高換手 vs benchmark 單次買入不對稱)。屬學術慣例(論文亦同),但**報告超額報酬時必須標註**。

## 十三、事件驅動取樣 + Triple-barrier 標籤實驗(2026-08-23 開始)

### 13.0 動機與設計

**動機**(承 §十二):日曆取樣下相鄰日子圖錨點重疊 7–8/10、標籤卻逐日翻轉(影本問題);原論文 Eq.(11)/Table 3 定義輸出為「下一時間步收盤漲跌」二分類,對此視野未作任何論證;§十一 h=5 已證明單純拉長視野無效。本節同時更換**取樣時機**與**標籤形式**,並逐一歸因。

**取樣**:因果 ZigZag 確認(`core/events.py::zigzag_confirm`)——收盤價自最近極值反向走滿 x=5% 的第一天為「確認日」= 決策日(轉折日事後才知,不可用,避免前視)。事件以完整序列計算(確認只用 ≤t 資料,跨 train/test 無洩漏)。
**標籤**:triple-barrier(`core/events.py::triple_barrier`)——自決策日起最多 T=20 交易日,收盤相對決策日先觸及 +5% → 1、先觸及 −5% → 0,皆未觸及以到期日報酬正負決定(維持二分類);不足 T 日者丟棄;訓練標籤以 train_end 截斷之 df 計算(embargo 自動達成)。
**方向特徵**(D 組):swing 方向 ±1、距轉折日天數/20,併入 FC1(`ChartGCN(extra_dim=2)`)。
**X 不變**:事件樣本直接自 elec_all h=1 dscache 以 (ticker, 決策日) 篩出(`test/event_data.py`),特徵逐位元相同,不重建。
**協定**:elec_all 450 檔,2016–2023 訓練(隨機 80/20 val)、2024 測試;Adam 1e-3 / wd 5e-5 / CE / 30 epochs / val F1 macro 選模 / date batch / paper_exact;seeds 42/43/44;不做回測。
**判準**:Acc > floor=max(p,1−p) 且預測分布平衡;以**事件日**為區塊 bootstrap 5,000 次報 Acc−floor CI 與 P(>floor)。

## 十七、表示法差分檢驗:管線的哪一步破壞了訊號(2026-08-25)

> 承 §13.4 老師建議的相似度比對。§13.4 只量了「子圖空間」一個點(一致率 50.16%,
> 距標籤置換 +1.7σ),無法區分兩種可能:(甲) 原始序列本來有訊號、被 PIP+VG 壓掉了;
> (乙) 隔日/短期方向本身就沒訊號。本節把管線的三個中間站都拿出來做同一個 k-NN,
> 唯一變因是輸入表示法。腳本 `analysis/repr_knn.py`。

### 17.1 設計

管線的三個中間站(同一次建構中一起產出,樣本逐筆對齊):

| 代號 | 表示法 | 形狀 | 維度 |
|---|---|---|---|
| R0 | 原始技術指標序列 | (140, 9) | 1,260 |
| R1 | PIP 抽點後 | (80, 9) | 720 |
| R2 | VG + 子圖(現行 Chart GCN 輸入) | (10, 4, 9) | 360 |

- **R0 → R1 的差距 = PIP 抽點丟掉的資訊**
- **R1 → R2 的差距 = VG + 子圖切分/排序丟掉的資訊**

凍結變因:同一批事件樣本(x=5% 因果 ZigZag,與 §13.4 完全同一批)、同一組標籤、
同一個庫/查詢切分(2016–2023 → 2024)、同一個距離(歐氏)、同一套對照(標籤隨機置換 ×20)。

面向網格:表示法 {R0,R1,R2} × 正規化 {sample-z, global-z} × k {5,20,50} × 標籤 {tb, nextday}。

指標:
- **主指標 Δσ** =(鄰居標籤一致率 − 置換均值)÷ 置換 SD
- 輔助:多數決 Acc vs floor(事件日區塊 bootstrap 3000 次、95% CI)
- 幅度面向:鄰居未來報酬均值 vs 查詢未來報酬的 Spearman ρ(不丟幅度資訊)

### 17.2 判定門檻(**於執行前定死,避免事後挑數字**)

某表示法要被認定「含可用訊號」,必須**同時**滿足:

1. **|Δσ| ≥ 3**(置換 SD 約 0.1pp,故 3σ ≈ 0.3pp)
2. **sample-z 與 global-z 兩種正規化同號**
3. **k = 5 / 20 / 50 三個 k 同號**
4. 輔助:多數決 gap 的 bootstrap 95% CI 下界 > 0

> 符號隨設定翻轉即判定為雜訊 —— 這正是 §13.4 六個設定中出現兩個負值的模式。

### 17.3 結論判讀表(執行前定義)

| 情況 | R0 | R2 | 結論 |
|---|---|---|---|
| 甲 | ≥3σ | ~0σ | 原始序列有訊號、被 PIP+VG 壓掉 → **Chart GCN 的表示法有害** |
| 乙 | ~0σ | ~0σ | 短期方向本身無訊號 → 表示法不是主因,**題目設定才是** |
| 丙 | ~0σ | ≥3σ | 子圖創造了新訊號 → Chart GCN 表示法確有價值 |
| 丁 | 皆 ≥3σ 且相近 | | 有訊號但表示法無差別 → 問題在模型端 |

§13.4 已測得 R2 = +1.7σ(未達門檻),故丙、丁已被排除;結論只會是甲或乙。

### 17.4 結果(`analysis/output/repr_knn.json`;庫 50,395 / 查詢 8,017)

### 17.5 兩個必須註記的細節

**(1) R2 的一致性略高於 R0,是維度假象,不是子圖創造了資訊。**
資訊上 R2 ⊂ R1 ⊂ R0(子圖節點 ⊂ 80 個 PIP ⊂ 140 天),子圖轉換不可能生出原始序列沒有的內容。
Δσ 的一致性隨維度下降而上升(1,260 → 720 → 360),是 k-NN 在高維下距離集中(curse of
dimensionality)導致近鄰失去意義的典型表現 —— 量到的是**度量的可辨識度**,不是資訊量。
故此處不可反推「子圖表示法有價值」。

**(2) 本檢驗的效力邊界。** k-NN 用等權歐氏距離,對 1,260 維一視同仁;
訓練過的模型可以學到加權投影,是 k-NN 無法利用的。因此本節否證的是
**「圖表型態相似 → 未來相似」這個前提**(即技術分析與 Chart GCN 動機的核心假設),
而非「任何模型都學不到東西」。但這個前提正是原論文 §1 的立論基礎,
故否證力道落在論文的**動機層**,比落在模型層更強。

**否證鏈第 11 維:表示法差分(原始序列 / PIP / 子圖)—— 三者皆未檢出訊號 ✗。**
> **【2026-09-05 措辭更正,見 §19.2 第 2 項】**「= 隨機」應讀作「未檢出」:
> 本檢驗的效力有限(n_eff ≈ 1,599 → Accuracy 的最小可偵測效應約 2.5pp),
> 正確陳述是「若有效應,其大小小於可偵測門檻」,而非「效應不存在」。
與 §16.1(1D-CNN 對照)並讀:表示法不是瓶頸,**短期方向本身的訊噪比才是**;
此與 Jiang, Kelly & Xiu (2023, *Journal of Finance*) 在全 CRSP 樣本上 20/60 日
方向準確率僅 52.5–53.6% 的天花板一致。
