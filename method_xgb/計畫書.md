## 0. 一句話摘要

**從日 OHLCV 生成 100–200 個技術指標 → 丟進 XGBoost → 用 feature importance 把弱指標剔掉 → 用留下的指標重訓 XGBoost → 與 Chart-GCN 用同一套協定（Acc / F1 / 十分位多空 H-L）比較，決定後續主線。**

## 1. 背景與動機

### 1.1 老師的原話（逐字稿還原）

| 逐字稿 | 還原 |
|---|---|
| 可以升技術指標的嗎 | 可以**生成**技術指標嗎 |

### 1.2 為什麼現在做這件事

- Chart-GCN 復現線已完結：10 個維度的否證鏈（換市場、掃參數、加資料、分族群、分流動性、模型對照、拉長視野、事件取樣、縮短窗格、週視野）全部停在 ~50–54% 的資訊天花板，論文宣稱的 69.26% 無法重現。
- 07-22 已做過 XGBoost 同條件對照，但那次只用**論文的 9 個指標**（n=140 的超長窗口），結果與 Chart-GCN 同水準（53.87% / F1m 塌縮）。**沒有測試過「大量、多尺度指標」是否有更多資訊。**
- 08-25 週報提出改用 JKX（Jiang, Kelly & Xiu 2023）的**十分位多空**評估：Accuracy 量的是「會不會看大盤」，H-L 量的是「會不會選股」。這條 XGB 線從一開始就用這套協定評估。
- 表格式 XGBoost 訓練一次只要幾十秒到幾分鐘，可解釋（哪個指標有用一目了然），適合快速迭代，比 GCN 管線（建 dataset 10–30 分鐘）快一個數量級。

### 1.3 這條線要回答的問題

1. **Q1 資訊天花板**：把指標從 9 個擴充到 200 個、視窗從單一 n=140 擴充到 5–120 多尺度，台股 h=1/5/20 日漲跌的可預測性有沒有提升？還是仍停在 floor？
2. **Q2 篩選是否有效**：剔掉低重要性指標後重訓，樣本外表現是「不變」（雜訊被移除，模型更穩）、「變好」還是「變差」（丟掉了有用的弱訊號）？
3. **Q3 哪些指標留下來**：留下的指標是哪些族群（趨勢 / 動量 / 波動 / 量能 / 橫斷面）？跨 seed、跨年份是否穩定？
4. **Q4 跟 Chart-GCN 比**：同股票池、同標籤、同測試年，XGB-200 / XGB-pruned 的十分位 H-L、單調性 ρ 是否顯著優於 Chart-GCN 最佳實驗與 XGB-9？

### 2.2 時間切分（**時間序切分，不再用隨機 80/20**）

07-22 的 XGB 對照沿用 Chart-GCN 的「訓練期內隨機 80/20 切 val」。這在時間序列上會讓 val 與 train 同一天的樣本互相洩漏，early stopping 會過度樂觀。本線改成：

```
2016-01-01 ─────── 2022-12-31 │ 2023-01-01 ── 2023-12-31 │ 2024-01-01 ── 2024-12-31
          訓練 (train)         │       驗證 (val)          │       測試 (test)
                            purge h 日                  purge h 日
```

- **purge**：train / val / test 邊界各空出 h 個交易日（h 為標籤視野），避免標籤跨越邊界。
- **warm-up**：指標最長視窗 120 日，val 與 test 段從邊界往前多帶 250 列做 rolling 暖機，但暖機列不產生樣本（對齊 chartgcn `split_by_date(warmup_rows=...)` + `min_date` 的做法）。
- **測試集只碰一次**：所有篩選、調參只在 train + val 上做；test 是最後報告用。
- **延伸（可選）**：rolling-origin 三折（test = 2022 / 2023 / 2024）看結果是否只是 2024 這一年的特例。

### 2.3 標籤

| 名稱 | 定義 | 用途 |
|---|---|---|
| `y_bin_h{h}` | `close[t+h] > close[t]` → 1，否則 0；h ∈ {1, 5, 20} | 主標籤，與 Chart-GCN（h=1 論文 Eq.11、h=5 已做）對齊 |
| `y_cs_h{h}` | 當日 h 日報酬 > 當日**橫斷面中位數** → 1 | 副標籤，直接對齊十分位多空的「選股」目標，大盤漲跌被消掉 |
| `r_h{h}` | `close[t+h]/close[t] − 1` | 迴歸標籤（可選），並作為十分位評估的實現報酬 |

決策日 t 的所有特徵只能用 t 以前（含 t 收盤）的資訊。

## 3. 特徵：技術指標庫（目標 180–220 欄）

### 3.1 設計原則

1. **全部用 pandas / numpy 自己實作**，不依賴 `pandas_ta` / `TA-Lib`（本機未安裝，且 pandas_ta 與 pandas 2.3 / numpy 2.2 相容性不佳）。每個指標寫成獨立函數，附 docstring 寫公式與出處。
2. **只用 t 以前資料**：rolling / ewm / shift 一律往後看，不用 `center=True`，不用未來欄位。
3. **尺度不變**：價格類指標一律轉成「相對 close 的比率」或「在區間內的位置」，避免高價股 / 低價股不可比（樹模型不在意單調變換，但橫斷面排序需要可比）。例如 SMA 不直接用，改用 `close / SMA − 1`。
4. **多尺度**：同一指標套 5 組視窗 `W = {5, 10, 20, 60, 120}`，這是「一兩百個」最主要的來源。
5. **NaN 政策**：暖機期產生的 NaN 保留為 NaN（XGBoost 原生支援缺失值），不用 0 填補（0 對 z-score 類指標是有意義的值，會誤導）。
6. **每欄有 metadata**：`name, family, window, formula, source` 存成 `config/feature_catalog.csv`，之後報告「留下哪些族群」直接統計。

## 4. 模型：XGBoost

### 4.1 基準設定

```python
XGBClassifier(
    n_estimators=3000,          # 由 early stopping 決定實際棵數
    learning_rate=0.03,
    max_depth=5,
    min_child_weight=50,        # 樣本數 ~30 萬，防止葉子過小
    subsample=0.8,
    colsample_bytree=0.5,       # 200 欄時每棵樹只看一半，降低相關指標互搶
    reg_lambda=5.0,
    reg_alpha=0.0,
    tree_method="hist",
    eval_metric="logloss",      # 主；另外記錄 auc
    early_stopping_rounds=100,
    n_jobs=4,                   # 本機分頁檔限制，不開滿核心
    random_state=seed,
)
```

- 目標函數：主線 `binary:logistic`；副線 `reg:squarederror`（對 `r_h`）或 `rank:pairwise`（以日期為 group，直接優化橫斷面排序）。
- 樣本權重：不做類別平衡（全押跌 floor 54.2% 是已知的，用 F1 macro 與 H-L 看塌縮就好）。
- 超參數只在 val 上用小網格掃 `max_depth ∈ {3,5,7}`、`colsample_bytree ∈ {0.3,0.5,0.8}`、`min_child_weight ∈ {10,50,200}`，掃完固定，後續篩選流程不再動。
- Seed ∈ {42, 43, 44}，所有數字報 mean ± std。

### 4.2 記憶體與執行環境

- 樣本數估算：tw50 × 9 年 ≈ 11 萬列；tw500 ≈ 100 萬列 × 200 欄 float32 ≈ 800 MB。tw500 需分批算特徵、寫 parquet，再一次讀入。
- 執行前設定 `LOKY_MAX_CPU_COUNT=4`（本機分頁檔 512 MB 固定，多進程會 MemoryError）。
- 特徵矩陣快取為 `experiments/features_{pool}_{start}_{end}.parquet`，第二次跑直接讀。

## 5. 特徵重要性

### 5.1 三種量法（都算，以 5.2 的合成排名為準）

| 方法 | 計算方式 | 優點 | 缺點 |
|---|---|---|---|
| **Gain**（XGB 內建 `importance_type="gain"`） | 每次分裂帶來的 loss 下降總和 | 免費、快 | 偏好高基數連續欄；相關欄互搶時不穩 |
| **Permutation importance**（在 **val** 上） | 打亂某欄後 val logloss / AUC 的惡化量 | 直接量「對樣本外預測的貢獻」 | 相關欄互相替補時會低估；200 欄 × 5 次 ≈ 數分鐘 |
| **SHAP mean |value|**（可選，需 `pip install shap`） | TreeExplainer 在 val 子樣本（≤ 2 萬列）上算 | 有一致性保證、可看方向 | 額外套件 |

不用預設的 `weight`（分裂次數），那個對相關的技術指標最不穩。

### 5.2 穩定性：不要只看一次

1. 3 個 seed × 各方法 → 每欄得到 rank。
2. 額外用 rolling-origin：train 到 2020 / 2021 / 2022 各訓一次，看 rank 是否隨年份劇烈變動。
3. **合成排名** = 各 (seed, 方法) rank 的平均；同時記錄 rank 的 std 當「穩定度」。
4. 輸出 `experiments/importance_{tag}.csv`（欄：feature, family, gain, perm, shap, rank_mean, rank_std）與長條圖 `figs/importance_top50_{tag}.png`、族群彙總圖 `figs/importance_by_family_{tag}.png`。

### 5.3 相關性去重（篩選前先做）

- 對 train 特徵算 Spearman 相關矩陣，|ρ| > 0.95 的配對只留合成排名較高者。
- 記錄被去掉的欄與其「代表欄」，避免後面解讀時誤以為某指標「沒用」（其實是被同義欄取代）。

## 6. 剔除與重訓

### 6.1 主線（老師說的單次篩選）

```
Step 1  全 ~200 欄訓練 XGB-full（3 seeds）→ 合成重要性排名
Step 2  相關性去重（§5.3）
Step 3  剔除規則（三種都跑，作為敏感度分析）：
        R-a  保留累積 gain 達 90% 的欄
        R-b  保留合成排名前 K 欄，K ∈ {20, 40, 80}
        R-c  剔除 permutation importance ≤ 0（打亂後 val 反而變好或不變）的欄
Step 4  用保留欄重訓 XGB-pruned（同超參數、同 3 seeds）
Step 5  在 test 上比較 XGB-9（07-22 基線）/ XGB-full / XGB-pruned(R-a, R-b×3, R-c)
```

### 6.2 延伸（若主線有訊號再做）

- **遞迴剔除 RFE**：每輪剔掉最弱 25%，重訓，記錄 val 指標；畫「特徵數 vs val AUC / H-L」曲線，找轉折點。
- **族群消融**：一次拿掉一整族（趨勢 / 動量 / 波動 / 量能 / K 棒 / 統計 / 橫斷面），看哪一族拿掉掉最多。這比單欄重要性更能回答「什麼類型的資訊有用」。
- **只用橫斷面組**：驗證 G 組是否單獨就能撐起 H-L。

## 10. 風險與對策

| 風險 | 對策 |
|---|---|
| 結果仍是 ~50% floor（很可能） | 這本身就是答案：指標擴充 20 倍仍無訊號 → 否證鏈第 11 項。重點看 H-L 與 ρ，不只看 Acc |
| 重要性排名不穩（相關指標互搶） | 3 seed × 3 方法合成排名 + 相關去重 + 族群層級解讀 |
| 剔除後反而變差 | 三種剔除規則 + RFE 曲線，回報「特徵數 vs 表現」而不是單一結論 |
| 單一測試年（2024）特例 | rolling-origin 三折（2022/2023/2024）當穩健性檢查 |
| tw500 記憶體不足 | 分批算特徵寫 parquet；float32；n_jobs=4；必要時 stride=2 |
| 橫斷面特徵需要整個池 | G 組獨立在 panel 層算，其餘在單股層算；先合併再切分 |
| 存活者偏誤 | 與 Chart-GCN 線相同名單，比較時抵銷；報告時註明 |
